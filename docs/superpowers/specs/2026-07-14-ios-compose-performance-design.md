# iOS Compose 性能优化设计

日期：2026-07-14

## 目标

基于可重复测量定位并改善 iOS 上可感知的卡顿，重点覆盖首页地图、发现页列表与详情切换、碑刻书写三个高频场景。优化必须保持 Android 行为和视觉一致，不以删除产品功能或关闭必要动画换取指标。

本项目不承诺仅靠“减少重组”解决卡顿。重组次数、Canvas 重绘、路径计算、文字测量、图片解码、主线程 I/O 和 Debug 构建开销都属于候选原因，必须用基线数据区分。

## 当前风险证据

当前 `MapScreen` 在根组合层订阅 17 个 `StateFlow`，其中 `MapController.renderState` 又在 `ChinaMapView` 内重复订阅。地图监听器在组合函数体中注册，根层重组时会重复执行注册逻辑。

`ChinaMapView` 的 Canvas 在相机变化时投影地图路径、执行标签碰撞计算并测量文字。虽然已经存在 `GeoPathCache`，中心点或缩放变化仍会重新构造屏幕路径。发现页网络图片和碑刻多层路径绘制也可能造成 iOS 主线程或 GPU 压力。

这些是高优先级假设，不是已经证明的根因。

## 测量场景

使用固定数据和固定操作脚本，分别记录 Debug 与 Release 构建。每个场景至少运行五次，第一次作为预热，不计入中位数。

### 场景 A：首页地图

- 冷启动进入首页并等待地图稳定；
- 连续拖动和缩放地图 10 秒；
- 打开、关闭省份详情浮层；
- 展开并收起地图工具菜单。

### 场景 B：发现页

- 进入发现页并等待首屏图片完成；
- 连续滚动推荐列表；
- 点击带头图的推荐项进入详情；
- 返回列表并重复一次。

### 场景 C：碑刻

- 打开已有多笔画碑刻；
- 连续书写 10 秒；
- 撤销三次并保存；
- 返回列表滚动全部碑刻卡片。

## 采集信号

- 使用 `xcrun xctrace` 的 `Time Profiler` 和 `Animation Hitches` 模板记录主线程热点、长帧和 CPU 时间；
- 使用无可见 UI 的 Debug 探针记录关键 Composable 的重组次数；
- 使用平台日志标记地图手势、详情转场、图片完成和笔画提交区间；
- 记录每个场景的中位帧耗时、P95 帧耗时、超过一帧预算的帧比例、主线程最重函数和根层重组次数；
- 同时保存相同操作节点的前后截图，排除视觉或状态回归。

模拟器数据用于相对前后比较，不伪装成真机绝对性能。若有可用 iPhone，则补充相同 Release 场景；没有真机时在交付说明中明确标注证据边界。

## 优化顺序

### 1. 缩小重组范围

- 根层只订阅真正影响整体布局的状态；
- 地图主题暴露为独立、`distinctUntilChanged` 的状态，不再让 `MapScreen` 为全部 `renderState` 变化重组；
- 详情浮层、相册标记、成就提示和工具菜单各自在叶子组件订阅所需状态；
- 使用 `DisposableEffect` 和 `rememberUpdatedState` 稳定注册地图监听器；
- 确保列表 item 使用稳定 key，避免图片加载或局部状态导致整列重组。

### 2. 降低地图每帧计算

- 把边界简化和地理坐标预计算保留在数据变化阶段；
- 按缩放档位缓存文字测量结果，手势移动时只更新位置和碰撞结果；
- 检查路径缓存是否能复用世界坐标路径与 Canvas 变换，避免每个相机帧创建全部 `Path`；
- 手势进行中降低非关键标签和图片标记的更新频率，手势结束后恢复完整状态；
- 只有证据表明当前光晕或多层绘制是 GPU 热点时，才合并对应绘制层。

### 3. 控制图片与转场成本

- 发现页图片按目标容器尺寸解码，避免加载远大于显示尺寸的位图；
- 列表与详情复用相同图片请求和稳定尺寸，保持已经实现的头图连续转场不抖动；
- 预取仅覆盖下一屏和即将进入的详情头图，避免一次性抢占主线程与内存。

### 4. 控制碑刻绘制成本

- JSON 只在数据变化时解析；
- 已完成笔画转换为目标尺寸 Path 后缓存；
- 所有静态凿刻层在一个缓存绘制阶段完成；
- pointer move 只追加活动笔画缓冲区并请求画布重绘，不复制完整笔画列表；
- 碎屑与破损边使用确定性缓存，不在每帧重新随机生成。

## 决策规则

每项优化必须对应基线热点：

- 如果根层重组与长帧时间相关，先拆状态订阅和监听器；
- 如果重组不高但 Canvas CPU 高，优先路径、标签和绘制缓存；
- 如果图片完成时出现峰值，优先解码尺寸、请求复用和预取范围；
- 如果只有 Debug 构建卡顿，仍修复明显无效工作，但以 Release 数据判断用户体验是否达标；
- 任何优化使另一个核心场景 P95 退化超过 10%，必须回退或继续调整。

## 测试与回归

- 为地图主题去重、监听器生命周期和状态切片增加单元测试；
- 为路径缓存失效条件、标签测量缓存和碑刻缓存 key 增加测试；
- 运行 `:shared:allTests` 和 Android 单元测试；
- Android UI/runtime 变化执行项目规定的安装、ADB 交互和前后截图；
- iOS 使用相同固定脚本完成构建、安装、交互、截图、日志与性能轨迹；
- 验证地图点击、双击下钻、拖动缩放、发现页转场和碑刻书写没有行为回归。

## 性能验收

在固定设备、固定构建类型和固定脚本下：

- `MapScreen` 根层在 10 秒纯地图拖动期间不因相机帧持续重组；
- 已确认的根层无效重组次数至少下降 80%；
- 若基线 P95 超过一帧预算，目标场景 P95 至少改善 20%；
- 任一核心场景 P95 不得比基线退化超过 10%；
- 碑刻连续书写不得丢点、断线或使顶部栏和工具栏持续重组；
- 发现页图片完成后卡片尺寸不改变，列表到详情仍保持连续；
- 无新增崩溃、内存异常或序列化错误。

性能结论必须同时附带测量配置、原始轨迹或汇总、前后数值和可见回归截图。只报告“感觉更顺”不满足完成标准。
