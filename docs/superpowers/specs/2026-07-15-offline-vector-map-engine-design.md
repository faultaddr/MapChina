# 离线矢量地图引擎设计

## 1. 目标

将足迹首页的默认地图升级为一套完全离线、自绘制、数据驱动的中国及周边区域矢量地图引擎。视觉语言参考自然资源部标准地图，但针对手机端降低信息密度，并保留足迹点亮、定位、照片、下钻和主题切换等产品能力。

本设计确认以下产品决策：

- “标准地图”成为新的默认主题；水墨、古舆图、宣纸、星夜和山水继续作为可选主题。
- 地图由 Compose Canvas 基于矢量数据实时绘制，不使用整张地图图片，不依赖在线瓦片或在线地图 SDK。
- 全国视图采用移动端克制密度。
- 未点亮省份为近白色；已点亮省份使用低饱和玉青填充并加深边界。
- 数据范围为中国及周边区域，不扩展为可无限平移的世界地图。
- 离线数据包括中国国界、海岸线、行政区、周边陆地、主要河流、城市标签、重要岛屿和完整十段线。

## 2. 当前问题

现有地图具备共享 Compose Canvas、Web Mercator 投影、手势、路径缓存和省市区下钻，但还不是完整矢量引擎：

- Android 与 iOS 各自读取散落的 GeoJSON 文件，数据重复打包。
- `MultiPolygon` 只保留最大面，岛屿、飞地和多面行政区可能丢失。
- `Polygon` 只保留第一个环，湖泊和内环无法表达。
- 周边国家轮廓由低精度坐标手工近似，且全国视图不显示。
- 几何、主题样式、标签规则和业务覆盖状态耦合在单个 Canvas 绘制流程中。
- 缺少统一数据版本、来源、校验哈希、空间索引和多级精度。
- 全国图视觉更像省份拼图，海陆关系、经纬网和国界层级不足。

## 3. 非目标

- 不实现全球离线地图或道路级导航。
- 不接入在线瓦片、Mapbox、MapLibre 或高德底图。
- 不在全国视图显示所有城市、河流、山脉和岛礁名称。
- 不把参考图作为位图背景。
- 不在本阶段改变足迹判定、定位、同步、照片或景点业务模型。
- 不用未审核地图数据替代发布前的地图审核流程。

## 4. 总体架构

### 4.1 构建期数据编译器

新增 JVM 构建工具 `tools/map-compiler`，使用结构化 JSON 解析将来源数据编译为应用专用离线包。编译器负责：

- 解析 GeoJSON 和转换后的标准地图矢量数据；
- 保留点、线、面、多面和内环；
- Web Mercator 投影前的经纬度合法性检查；
- 拓扑弧去重和坐标量化；
- 按缩放层级生成多级简化几何；
- 生成要素包围盒、空间网格索引和标签锚点；
- 输出数据清单、来源、版本、审图号和 SHA-256 校验值；
- 生成 Android 与 iOS 共用的同一份逻辑数据包。

运行时不解析庞大的原始数据，也不执行 Douglas-Peucker 等全量简化操作。

### 4.2 共享运行时模块

引擎拆为以下边界清晰的共享模块：

- `VectorMapPackageLoader`：按清单加载并校验离线包；平台层只负责读取 App 资源。
- `VectorGeometryDecoder`：将量化拓扑数据解码为完整几何模型。
- `VectorSpatialIndex`：根据视口和缩放级别查询可见要素。
- `VectorMapScene`：管理当前层级、加载状态、可见图层和业务覆盖状态。
- `VectorPathCache`：缓存投影后的 Compose `Path`，键由数据版本、要素、LOD 和投影状态组成。
- `VectorLabelEngine`：负责标签优先级、碰撞检测和跨缩放稳定性。
- `VectorMapRenderer`：按样式表和图层顺序绘制 Canvas，不读取业务仓库。
- `MapStyleSheet`：描述颜色、线宽、透明度、缩放阈值和图层可见性。

`MapController`、`ViewportState` 和现有业务事件继续作为界面层契约。迁移期间由适配器把旧覆盖数据转换为新场景状态。

### 4.3 完整几何模型

公共模型必须支持：

- `Point` 与 `MultiPoint`；
- `LineString` 与 `MultiLineString`；
- `Polygon`，包含一个外环和零个或多个内环；
- `MultiPolygon`，包含所有面及其内环；
- 每个要素的稳定 ID、图层、属性、包围盒、最小/最大显示缩放级别和标签锚点。

渲染器不得再通过“最大点数”选择单一面。台湾、海南、舟山群岛、港澳和其他离岛必须按数据完整绘制。

## 5. 离线数据包

### 5.1 包结构

逻辑目录如下：

```text
map-package/
  manifest.json
  base/
    land-neighbors.topo
    coastline.topo
    graticule.meta.json
    rivers-major.topo
    islands-important.topo
  china/
    national-boundary.topo
    provinces-lod0.topo
    provinces-lod1.topo
    province-labels.json
    ten-dash-line.topo
  cities/
    <province-adcode>.topo
  districts/
    <city-adcode>.topo
  labels/
    national.json
    <province-adcode>.json
```

实际安装包可压缩或合并文件，但运行时必须保留以上逻辑分层，避免启动时加载全部区县。

### 5.2 分级加载

- 冷启动只加载 `manifest`、周边陆地、中国国界、省级 LOD0、全国标签和十段线。
- 放大到省级时加载省级 LOD1、主要河流和对应城市包。
- 放大到城市级时加载该城市区县包。
- 离开下钻区域后保留最近使用包的有界 LRU 缓存，超限后释放。
- 当前精度包未完成加载时继续显示上一层级几何，不出现空白闪烁。

### 5.3 数据来源与合规

- 中国国界、海岸线、重要岛屿和南海断续线以自然资源部标准地图 EPS 版为基准转换和校验。
- 省市区数据在进入正式包前必须通过行政区覆盖审计和标准地图目视复核。
- 周边区域仅用于地理参照，使用经过许可的矢量海陆数据，并统一按公开地图内容表示规范校正关键边界表达。
- `manifest.json` 记录 `dataVersion`、来源名称、来源版本、审图号、编译器版本、生成时间和每个资源的 SHA-256。
- 标准地图经裁切、缩放、改色或叠加业务内容后，正式公开发布前必须送自然资源主管部门审核；开发包不得被描述为已获审图批准。

## 6. 视觉与图层

### 6.1 标准地图默认主题

- 海域：清透浅青纯色，允许极弱明度变化，不使用纸张纹理或装饰性渐变。
- 周边陆地：中性浅灰，边界为细灰线，不抢占中国国土层级。
- 中国国土：未点亮区域为近白色。
- 已点亮省份：低饱和玉青填充，边界比未点亮省份略深，不按足迹数量改变色阶。
- 国界：深灰主线加一层低透明淡蓝外沿；外沿仅在全国级可见。
- 省界：低对比细灰线；放大后逐步减细，避免视觉膨胀。
- 经纬网：全国视图显示稀疏主网，颜色低于省界，不显示密集坐标数字。
- 十段线：十个独立、连续、圆端短曲线，沿用已校准的参考坐标。
- 标签：全国视图只显示省级名称和必要地理名称；省会、河流、城市、区县按缩放级别逐层出现。

### 6.2 绘制顺序

1. 海域底色；
2. 经纬网；
3. 周边陆地填充及边界；
4. 中国国土基础面；
5. 未点亮/已点亮行政区覆盖；
6. 国界、海岸线、省市区边界；
7. 主要河流与重要岛屿；
8. 十段线；
9. 行政与地理标签；
10. 足迹、照片、定位、脉冲和庆祝动画；
11. 原生 Compose 浮层与地图工具。

任何主题都只能改变样式，不能改变国界、行政区、十段线或重要岛屿数据。

## 7. 标签与交互

### 7.1 标签优先级

优先级从高到低为：

1. 当前选中区域；
2. 用户足迹或照片关联标签；
3. 当前下钻层级名称；
4. 省级名称与省会；
5. 普通城市；
6. 主要河流和周边地理参照。

标签引擎按稳定排序执行碰撞避让。缩放过程中使用相同锚点和显示滞回，避免边界附近标签反复抖动。

### 7.2 交互

- 手势、双击缩放、长按、定位和相机恢复行为保持现状。
- 命中测试由空间索引先筛选候选要素，再执行点在多边形内判断；内环区域不得命中外部行政区。
- 全国图点击省份、省图点击城市、城市图点击区县的业务路径保持不变。
- 加载更精细数据时保持旧层可交互，切换完成后一次性替换，避免半帧状态。
- 主题切换只更新样式表，不重新解析或复制几何。

## 8. 性能设计

- LOD 在构建期生成，运行时只选择合适精度。
- 空间索引先裁剪不可见要素，Canvas 不遍历全国所有区县。
- 投影后的路径按数据版本、LOD、相机量化状态缓存；轻微平移复用缓存并施加变换。
- 标签测量结果按文本、字体和样式缓存。
- 全国场景的首个可交互矢量帧目标为加载器启动后 750 ms 内。
- Pixel 9 Pro 与 iPhone 17 Pro 上连续 10 秒平移/缩放的目标为 60 fps，P95 帧时间不超过 16.7 ms，不出现超过 50 ms 的长帧。
- 全国场景新增工作集目标不超过 40 MiB；进入单个城市最深层级后不超过 75 MiB。
- 当前 Android 单平台边界/区县源数据约 17.7 MiB。正式编译包目标不超过 26 MiB，发布构建不得同时保留完整旧数据和新数据副本。

性能数字是验收门槛；达不到时必须通过数据简化、索引和缓存修正，不允许通过删除用户确认的图层来规避。

## 9. 错误与降级

- 清单或资源哈希不匹配时拒绝加载该数据版本，并记录明确诊断信息。
- 单个下钻包损坏时保持上一层级地图，向界面暴露可恢复错误，不让 Canvas 崩溃。
- 迁移阶段保留旧地图渲染器作为功能开关降级路径。
- 新引擎通过全国、省、市、区县和双端设备验收后，移除旧运行时数据副本与降级开关。
- 正式版不存在“邻区加载失败后使用手绘近似边界”的路径。

## 10. 迁移阶段

### 阶段 A：数据编译器与几何内核

- 建立包清单、完整几何模型、Topo 解码、空间索引和数据审计测试。
- 将现有省级数据编译为首个离线包，与旧地图做轮廓差异对比。

### 阶段 B：全国默认地图

- 实现标准地图样式、海陆、经纬网、周边区域、国界、省界、标签和十段线。
- 接入点亮状态、选择、定位和足迹覆盖。
- 在功能开关后完成 Android/iOS 双端视觉与性能验证。

### 阶段 C：省市区下钻

- 迁移城市和区县包的按需加载、命中测试、标签与相机恢复。
- 验证港澳台、岛屿、多面和内环场景。

### 阶段 D：默认切换与清理

- “标准地图”成为新安装和无设置用户的默认主题。
- 保留其他主题并切换到共享准确几何。
- 删除旧散装数据、手绘周边轮廓和旧解析路径。
- 生成发布地图审核材料。

## 11. 测试与验证

### 11.1 自动测试

- 编译器：来源解析、量化往返误差、拓扑弧复用、LOD 误差和哈希稳定性。
- 几何：多面、内环、岛屿、包围盒、点在多边形内和视口裁剪。
- 数据审计：中国及省市区要素数量、经纬度四至、港澳台、海南、重要岛屿和十段线完整性。
- 标签：优先级、碰撞、稳定排序、缩放滞回和屏幕边缘裁剪。
- 状态：点亮填充、主题切换、下钻、返回全国和相机恢复。
- 错误：损坏清单、缺包、哈希失败和旧引擎降级。

### 11.2 Android 设备验证

每个 UI/运行时阶段必须执行项目铁律：

1. `./gradlew installDebug`；
2. 使用 `adb shell monkey` 启动；
3. 使用 `adb shell input tap/swipe` 验证全国、缩放、下钻、返回和主题切换；
4. 保存改动前后截图；
5. 检查 logcat 中的崩溃和 ANR；
6. 用 Perfetto、gfxinfo 或 Compose trace 验证帧时间。

### 11.3 iOS 设备验证

- 使用 iPhone 17 Pro 模拟器完成 Debug 构建、安装、启动和等价交互截图。
- 使用 Time Profiler 和 Animation Hitches 验证解析、路径构建和缩放帧时间。
- 对比 Android/iOS 的相机范围、图层顺序、颜色、标签和十段线位置。

## 12. 验收标准

以下条件全部满足后，离线矢量地图引擎才算完成：

- 默认首页是自绘标准地图样式，无位图底图和网络地图依赖。
- 中国及周边海陆、国界、省界、主要河流、重要岛屿、稀疏经纬网和完整十段线可按层级显示。
- 未点亮省份近白，已点亮省份为低饱和玉青，足迹交互与下钻行为无回归。
- 完整支持多面和内环，关键行政区与岛屿没有因“最大面”逻辑丢失。
- 城市和区县包按需加载，加载过程不白屏、不抖动。
- 标准地图以外的现有主题仍可使用同一套准确几何。
- Android 和 iOS 的视觉、功能、离线行为和性能门槛均通过设备证据验证。
- 正式发布包只包含新数据管线，并完成所需地图审核与审图号处理。
