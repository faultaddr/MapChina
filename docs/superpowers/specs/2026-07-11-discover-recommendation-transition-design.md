# 发现推荐头图与详情连续转场设计

> 日期：2026-07-11  
> 状态：按用户明确方向实施  
> 范围：发现 Tab 的“推荐去点亮”列表子项到景点详情页

## 1. 体验目标

“推荐去点亮”不再是一组白底信息卡。每个景点子项直接以景点头图为背景，让用户在扫列表时先看见目的地，再读取名称、等级和可点亮范围。

点击子项后，用户不应感知为“列表消失、详情页突然出现”。被点击的头图从原卡片位置扩展到屏幕顶部的详情头图区域，页面底色从点击中心向外晕染；图片到位后，景点详情正文淡入。整个过程应像同一张图自然长成详情页。

## 2. 采用方案

采用 **页面内过渡覆盖层 + 详情头图接棒**，不依赖 Navigation3 的实验性共享元素接口。

选择原因：

- 可以精确读取 LazyColumn 中每张卡片的真实坐标。
- KMP、Android 和 iOS 共用 Compose 实现，不引入平台特有动画。
- Coil 已经加载过列表图片，覆盖层和详情页复用同一 URL 时可命中缓存，减少闪白。
- 动画的坐标、圆角、背景晕染和导航时机都可测试，不受默认导航转场实现变化影响。

不采用的方案：

- **先铺满全屏再回缩为头图**：戏剧性更强，但有一次多余的尺寸反转，容易产生顿挫。
- **普通缩放 + 淡入详情**：实现简单，但无法形成“列表背景长成详情”的空间连续性。

## 3. 推荐卡片

每个列表子项高度为 `148.dp`，圆角为 `8.dp`：

- 景点 `imageUrl` 以 `ContentScale.Crop` 全幅铺底。
- 无图时使用深绿色背景和山景图标，不伪造远程图片。
- 叠加自上而下的透明到深色渐变，确保白色文字在亮图和暗图上都可读。
- 左上角显示两位排名，右上角显示 `5A / 4A / 自定义`。
- 底部显示景点名称、地点摘要和“可点亮”理由。
- 整张卡片是点击热区，语义描述为“打开景点详情：{景点名}”。

原有排名圆块、箭头和独立浅绿色理由条移除，减少信息碎片。

## 4. 点击与转场

列表卡片通过 `onGloballyPositioned` 记录 `boundsInRoot()`。点击后：

1. 锁定本次目标，忽略重复点击。
2. 在 Discover 根布局顶部绘制过渡覆盖层，初始矩形与被点击卡片完全重合。
3. 用 `420ms` 的 `FastOutSlowInEasing` 将矩形插值到：左上角 `(0, 0)`、宽度为页面宽度、高度为 `320.dp`。
4. 圆角从 `8.dp` 插值到 `0.dp`。
5. 页面背景色以卡片中心为圆心向外扩散，最终覆盖整个视口。
6. 排名和列表辅助信息在前半程淡出，标题和等级保留到最终头图状态。
7. 动画完成后导航到 `AttractionDetailScreen(fromDiscover = true)`。

转场期间保留原列表作为底层，覆盖层拦截输入，避免滚动或二次点击破坏空间关系。

## 5. 详情页接棒

详情页的图片源按以下顺序去重：

1. `attraction.imageUrl`
2. `detail.imageUrls`

这样详情页第一张图与推荐卡使用同一 URL。通过发现转场进入时：

- 详情头图从 `scale = 1f`、`alpha = 1f`、`offsetY = 0f` 开始。
- 不再执行现有的 `0.82x → 1x` 二次放大。
- 返回按钮和正文仍按短延迟淡入，保持层级建立感。

从地图、搜索等其他入口进入详情时，保留现有头图放大动画。

## 6. 状态与异常

- 图片加载失败：卡片和详情显示相同的深绿色占位，不闪白。
- 卡片坐标尚未测量：直接导航到详情，不执行错误起点动画。
- 动画进行中：后续点击被忽略。
- 景点详情数据缺失：沿用现有“景点信息不可用”状态。
- 用户返回：使用现有 Navigation3 返回，不倒放长动画，保证操作快速。

## 7. 验证标准

- UI 测试证明推荐卡有头图语义、标题、等级和理由。
- 动画时钟测试证明点击后不会立即导航，`420ms` 后只导航一次。
- 纯函数测试覆盖起始矩形、中间插值和最终 `320.dp` 头图矩形。
- Android 设备截图证明列表子项使用真实景点图背景。
- Android 设备连续截图或录屏证明点击图像从列表位置扩展到详情头图，没有白屏、二次缩放或文本重叠。
- 1.5 倍字体下卡片名称和理由不遮挡等级，列表仍可滚动。
