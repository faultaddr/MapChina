# MapChina「数字山河」网站重构设计

## 1. 背景

现有 `website/` 已具备 Next.js 16、Tailwind CSS 4、next-intl、Framer Motion、React Three Fiber、景点与社区公开 API、SEO 路由和 standalone 输出，但当前成品仍有明显原型感：首屏以下大量使用 emoji、纯色占位和缺失数据；主题区没有展示真实 App 资产；下载按钮指向空链接；移动端主题选择器造成横向溢出；中文硬编码混入国际化页面；lint 基线存在 8 个错误。

本设计取代 `docs/superpowers/specs/2026-06-14-website-design.md` 中已经过时的 Next.js 15、游录路由和正式商店下载假设。实现继续复用现有技术栈，不重建项目。

## 2. 已确认决策

- 同时优化产品官网与景点/社区内容站。
- 首页的 App 内测转化与内容分发同等重要。
- 视觉方向采用「数字山河」：保留深色地图记忆点，将内容与 App 成长体系并列呈现。
- 落地深度采用全站体验重构，而非单纯换肤或扩张为搜索平台。
- 数据采用真实 API 优先、精选内容兜底的混合策略。
- App 尚未上架，不显示虚假商店入口；统一使用“即将上线 / 参与内测”。
- “参与内测”通过预填主题和正文的邮件发送到 `cuferpan@gmail.com`。

## 3. 目标与非目标

### 3.1 目标

1. 建立统一、可识别、兼具现代数字感与东方旅行气质的「数字山河」品牌体验。
2. 让用户可以同等清晰地浏览景点/社区内容，或申请参与 App 内测。
3. 在 API 异常、超时或内容不足时仍提供可信、完整的浏览体验。
4. 重做首页、景点列表与详情、社区列表与详情、下载和关于页。
5. 修复响应式、可访问性、国际化、链接、图片兜底和 lint 基线问题。
6. 通过生产构建，在本机 `127.0.0.1:3100` 运行可访问的生产服务。

### 3.2 非目标

- 不增加站内搜索、复杂筛选、无限滚动、CMS 或主题路线编辑器。
- 不增加网页账号、登录、发帖或评论能力。
- 不新增后端接口或数据库。
- 不伪装成已经上架的 App，不展示不可用的 App Store 或 Google Play 按钮。
- 不改动 Android/iOS App 产品功能。

## 4. 信息架构

### 4.1 全局导航

桌面导航保持 `景点 / 社区 / 关于 / 参与内测`。导航在深色首屏上使用高对比浅色样式，离开首屏后过渡为暖白半透明背景。移动端使用完整抽屉菜单，支持键盘操作、关闭按钮、遮罩点击和页面滚动锁定。

所有内部链接保留当前 locale，不依赖中间件二次猜测语言。页脚包含产品定位、主导航、语言入口和内测 CTA。

### 4.2 首页

首页按以下顺序构成完整叙事：

1. **数字山河首屏**：深夜蓝地图场景、品牌口号、简短价值说明；同级提供“参与内测”和“开始探索”。
2. **此刻，山河正在发生**：景点精选与社区故事并列，证明内容活力。
3. **四条产品路径**：以 `足迹 / 发现 / 山河 / 我的` 对齐当前 App 结构，取代旧的六个 emoji 功能格。
4. **地图主题**：使用 App 现有主题资源展示经典、水墨、古舆图、宣纸、星夜和山水，不再使用纯色块。
5. **参与内测**：明确“即将上线”，解释内测价值并提供邮件申请入口。

### 4.3 景点

- 列表页以可浏览内容为主，展示图片、名称、地区、简介和有来源的真实数据。
- 详情页提供大图、层级清晰的基本信息、描述、真实访问数据和相关景点推荐。
- API 内容不足时可补入精选景点；精选项必须标记为“编辑精选”，不得伪造 ID 对应的远程详情或实时统计。

### 4.4 社区

- 列表页使用统一旅行故事卡片，展示封面、标题、作者、摘要及真实互动数据。
- 详情页形成可阅读的故事版式，优先展示封面、作者与正文；没有封面时使用语义化地图视觉兜底。
- API 内容不足时可补入精选故事；精选内容使用本地详情数据，不制造点赞或评论数。

### 4.5 下载与关于

- 下载页重构为内测落地页，展示产品价值、支持平台、尚未上架状态与邮件申请 CTA。
- 邮件链接使用 `mailto:cuferpan@gmail.com`，预填中英文主题和简短申请模板。
- 关于页说明产品理念、四条产品路径、隐私友好的记录定位和开源仓库入口。

## 5. 视觉系统

### 5.1 色彩与字体

- 深夜蓝：品牌首屏、地图与深色 CTA 区域。
- 碧玉绿：主交互、激活状态和地图信号。
- 鎏金：足迹、高光、成长与编辑精选标识。
- 暖白：长内容阅读背景和浅色导航。
- 墨色与青灰：正文和次级信息。

中文标题使用 Noto Serif SC，正文使用 Noto Sans SC；英文标题使用 Playfair Display，正文使用 Inter。字体仍由 `next/font` 管理。

### 5.2 图形与媒体

- 移除 emoji 和无意义的首字大色块。
- 共享线性 SVG 图标，保证样式一致且不引入新图标依赖。
- 复用 App 已有主题背景、徽章或地图资产；复制到 `website/public/` 后由 Next Image 管理。
- 没有真实图片时，使用与地区或内容类型相关的地图渐变兜底，并提供准确替代文本。

### 5.3 动效与降级

- 保留轻量地图呼吸、内容进入和按钮反馈。
- 所有进入动画只播放一次，不阻止内容在无 JavaScript或截屏场景下可见。
- 遵守 `prefers-reduced-motion`；低性能或小屏设备默认静态 SVG 地图，不加载 Three.js 场景。
- 生成粒子数据使用确定性算法，避免渲染期间调用 `Math.random()`。

## 6. 组件边界

### 6.1 布局组件

- `Navbar`：导航、滚动状态、locale 保留和内测入口。
- `MobileMenu`：抽屉、焦点与滚动管理。
- `Footer`：全站导航、语言入口、联系与品牌信息。
- `PageHero`：列表、详情、下载和关于页的统一头部。

### 6.2 内容组件

- `AttractionCard`：景点图片、地区、简介和真实指标。
- `StoryCard`：社区封面、标题、作者、摘要和真实互动数据。
- `SectionHeading`：区块标题、引导说明和可选链接。
- `EditorialBadge`：标识本地精选来源。
- `MediaFallback`：图片缺失或加载失败时的地图视觉。
- `ContentState`：空、错误和未找到状态。

### 6.3 产品与转化组件

- `ProductPathCard`：足迹、发现、山河、我的四条产品路径。
- `ThemePreview`：展示真实主题资产并支持可访问切换。
- `BetaCTA`：统一“即将上线 / 参与内测”状态和邮件链接。

各组件只接受标准化 view model，不直接访问远程 API。

## 7. 数据流与容错

### 7.1 统一内容层

`lib/api.ts` 继续负责带超时的远程请求；新增标准化和组合层，将 API 返回转换成页面组件使用的 view model。页面只消费组合层，不处理缺失字段、远程异常或去重逻辑。

组合函数返回内容项和来源信息，支持：

- 对 API 字段进行安全标准化。
- 过滤没有稳定 ID 或关键显示字段的损坏记录。
- API 内容优先，按 ID 去重。
- 不足目标数量时从对应 locale 的精选数据补齐。
- 不将精选内容标记为实时，不生成虚假指标。

### 7.2 精选内容

精选景点与故事使用强类型本地数据，分别提供中文和英文内容。精选数据含本地 slug、标题、摘要、地区、封面或主题视觉，不含伪造的访问、点赞或评论数。

### 7.3 缓存与失败

- 列表维持 3600 秒 ISR，详情维持 1800 秒 ISR。
- API 继续设置有限超时，失败时返回结构化空结果而不是抛出到页面。
- 首页和列表页在 API 失败时完整展示精选内容。
- 远程详情不存在时显示明确的 404/未找到状态；本地精选详情使用本地数据渲染。
- 图片远程加载失败时切换 `MediaFallback`。

## 8. 国际化、SEO 与可访问性

- 所有页面文案进入 `zh.json` 和 `en.json`，不在页面中硬编码单一语言。
- 元数据、邮件主题、邮件正文和精选内容随 locale 切换。
- 详情页保留 `TouristAttraction` 或 `Article` JSON-LD；首页和列表页提供准确标题与描述。
- 页面只有一个 H1，后续标题按层级递进。
- 图片提供准确 alt；装饰 SVG 隐藏于辅助技术。
- 交互组件具备可见焦点、键盘操作和足够点击区域。
- 颜色对比达到 WCAG AA；动效支持 reduced motion。

## 9. 性能策略

- Three.js 只在支持条件下动态加载；移动端默认静态地图。
- 首页非交互区块优先使用 Server Components。
- 图片通过 Next Image 提供尺寸、响应式 `sizes` 和懒加载。
- 避免为简单图标增加第三方图标库。
- 不以新增重量级依赖解决布局或样式问题。

## 10. 测试与验收

### 10.1 自动化

- Vitest 覆盖 API 超时与错误、数据标准化、实时/精选合并、去重、locale 精选数据和 mailto 生成。
- React Testing Library 覆盖导航、移动菜单、主题切换、内容卡片、错误状态和内测 CTA。
- `npm run lint` 无错误。
- 测试全部通过。
- `npm run build` 生产构建成功。

### 10.2 浏览器验证

在桌面与 390px 移动视口验证：

- 中英文首页、景点、社区、详情、下载和关于页。
- 导航与移动抽屉可用，locale 不丢失。
- 页面没有横向溢出。
- 真实 API、精选补齐和纯精选三种状态都可正确显示。
- mailto 地址、主题和正文正确。
- 动效降级、图片失败兜底和键盘焦点正确。
- 保存改造前后关键页面截图。

### 10.3 项目级回归

按根目录 `AGENTS.md` 执行：

1. `./gradlew installDebug`。
2. 在 Android 设备或模拟器启动 App。
3. 使用 `adb shell monkey`、点击/滑动和 `screencap` 做基础回归。
4. 保存 App 回归前后截图，确保网站改动没有影响整体项目运行。

## 11. 本地生产部署

完成验证后停止开发服务，在 `website/` 执行生产构建，并以生产模式绑定：

```bash
npm run build
HOSTNAME=127.0.0.1 PORT=3100 npm start
```

选择 3100 是为了避开当前机器上另一个占用 3000 端口的项目。最终交付时服务必须仍在运行，且 `http://127.0.0.1:3100/zh` 与 `/en` 可访问。

## 12. 成功标准

1. 全站具备统一的「数字山河」视觉与内容语言。
2. 首页同时清晰承接内容浏览和内测申请。
3. 景点与社区页面在 API 正常或不可用时都可信、完整、可浏览。
4. 不存在空下载链接、伪造指标、emoji 功能格、纯色主题占位或移动端横向溢出。
5. 中英文、SEO、可访问性、lint、测试、构建和浏览器验证全部通过。
6. Android 设备回归完成并留存截图。
7. 本地生产服务在 `127.0.0.1:3100` 持续可访问。
