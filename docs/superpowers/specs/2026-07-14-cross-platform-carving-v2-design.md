# 跨平台碑刻 V2 设计

日期：2026-07-14

## 目标

让 Android 和 iOS 使用同一份碑刻数据、同一套摩崖视觉规则和一致的编辑行为。完成后，两端都必须能够：

- 新建碑刻并显示榜书凿刻效果；
- 在碑刻列表中稳定预览字迹；
- 打开另一端生成的碑刻数据；
- 在已有碑刻上续刻、撤销、清空并重新保存；
- 读取旧 Android V1 数据，且不会在后台静默改写或丢失旧数据。

本项目不新增文本模板、字体转笔迹、社交发布或数据库表字段。`strokeData` 仍以字符串形式存储和同步。

## 当前问题

Android 编辑器、列表预览和序列化直接依赖 `androidx.ink`。V1 JSON 记录画布像素坐标和像素笔宽，却没有格式版本或画布尺寸；iOS 对应页面仍是“不支持此平台”的占位页。

Android 当前编辑流程还会把“已有笔迹”和“本次新增笔迹”分开处理。只要用户续刻并保存，就有覆盖原笔迹的风险。列表预览直接使用原始像素路径，也不能可靠适配不同尺寸的预览卡片。

## 产品体验

### 入口与列表

Android 和 iOS 共用碑刻列表、地点上下文和空状态。列表卡片继续以真实岩壁图片为背景，叠加同一份共享碑刻渲染器。卡片显示地点、日期和碑刻字迹；点击进入编辑，长按触发删除确认。

列表滚动期间不得重复解析 JSON、重复构造随机碎屑或因图片加载改变卡片高度。卡片使用稳定尺寸和稳定 item key。

### 摩崖留刻编辑器

编辑器保留已经确认的“摩崖留刻”方向：

- 顶部显示返回、地点和保存；
- 中间为真实岩壁背景与可书写区域；
- 默认笔刷为 `MONUMENTAL`（榜书）；
- 榜书包含宽凿槽、内凹暗部、暖色石底、迎光边缘、破损边和确定性碎屑；
- 底部提供笔刷、粗细、颜色、撤销和清空；
- 空画布禁止保存，并显示现有提示“先刻下一笔，再落成碑刻”。

编辑已有碑刻时，原笔迹与新增笔迹属于同一份编辑文档。撤销按时间顺序移除最后一笔；清空清除全部笔迹，但只有用户点击保存后才写入数据库。返回而未保存时保留原数据。

## V2 数据文档

共享模型放在 `commonMain`，由 `kotlinx.serialization` 编解码。新数据只写 V2：

```json
{
  "version": 2,
  "canvasAspectRatio": 0.62,
  "strokes": [
    {
      "brushType": "MONUMENTAL",
      "sizeFraction": 0.09,
      "colorArgb": -14540254,
      "points": [
        { "x": 0.21, "y": 0.18, "pressure": 0.54, "elapsedTimeMillis": 0 },
        { "x": 0.24, "y": 0.22, "pressure": 0.61, "elapsedTimeMillis": 14 }
      ]
    }
  ]
}
```

字段语义：

- `version` 固定为 `2`；
- `canvasAspectRatio` 为创建时书写区域的 `width / height`，必须大于零；
- 点坐标 `x`、`y` 归一化到 `0..1`；
- `pressure` 归一化到 `0..1`，平台无法提供时使用 `0.5`；
- `elapsedTimeMillis` 相对当前笔画起点计时，必须单调不减；
- `sizeFraction` 相对画布短边归一化，不再存像素笔宽；
- `colorArgb` 保留现有 ARGB 语义；
- `brushType` 使用稳定字符串枚举，未知值回退到 `MONUMENTAL`，但不影响其他字段读取。

V2 保留压力用于数据完整性和后续笔刷能力；本次共享渲染仍使用每笔固定宽度，避免 Android Ink 与 iOS Canvas 因压力曲线不同产生视觉漂移。

解码器返回明确的 `Success`、`Empty` 或 `Invalid` 结果，禁止用“异常后返回空列表”掩盖损坏数据。编码前会过滤非有限数值、少于两个有效点的笔画，并对坐标、压力和笔宽做边界约束。

## V1 兼容策略

解码器先检查顶层 JSON：带 `version` 的对象进入 V2；顶层数组进入 V1 兼容解码。V1 原始字符串不会因为读取或预览而自动写回。

V1 没有保存原画布尺寸，因此无法数学上精确恢复原始留白。兼容策略明确采用“内容保真优先”：

1. 读取全部有效点和笔宽，计算包含笔宽的内容边界；
2. 使用记录中的 `previewAspectRatio`，若不存在则使用内容边界推导并约束在 `0.55..1.0`；
3. 在目标画布中保留几何比例并居中适配，四周至少保留 8% 安全边距；
4. 仅在内存中生成共享文档；
5. 用户明确编辑并保存后，才把当前可见布局编码为 V2。

如果 V1 JSON 损坏或没有任何有效点，页面显示“这方碑刻暂时无法读取”，提供返回操作，不提供会覆盖原数据的保存操作。

## 模块边界

### 共享文档与编解码

`commonMain` 新增以下职责单一的单元：

- `CarvingDocument`、`CarvingStroke`、`CarvingPoint` 和 `CarvingBrush`：跨平台领域模型；
- `CarvingDocumentCodec`：V2 编码、V2 解码和 V1 兼容解码；
- `LegacyCarvingNormalizer`：仅处理 V1 像素坐标的内容适配；
- `CarvingEditorState`：当前文档、活动笔画、撤销、清空、脏状态和错误状态；
- `CarvingPathCache`：按文档版本和目标尺寸缓存 Compose `Path`。

数据库、仓库和同步 DTO 继续传递原始 `strokeData`，不感知具体文档版本。

### 输入适配器

Android 保留 Ink 的低延迟输入能力，但完成一笔后立即转换为共享 `CarvingStroke`。iOS 使用 Compose 指针事件采集单指笔迹；有压力数据时记录压力，否则写入 `0.5`。

活动笔画使用可变点缓冲区，不在每个 pointer move 上复制整份文档。采样会合并同一时间且距离小于 0.5 物理像素的重复点；抬手时提交一次不可变笔画。多指手势不产生碑刻笔迹。

### 共享渲染器

编辑器和列表预览使用同一个共享 Canvas 渲染器。路径按目标尺寸构建，笔宽按目标画布短边恢复。榜书的阴影、凿槽、石底、边缘高光和碎屑在一个 Canvas 绘制阶段完成。

破损边和碎屑由文档内容生成稳定种子；同一份数据在每次重组和两端显示时保持一致，不在绘制阶段调用非确定性随机数。

背景图片和静态纹理使用 `remember`/资源缓存；路径使用 `drawWithCache` 缓存。活动笔画变化只使画布重绘，不应重组顶部栏、地点信息或工具栏。

## 状态与保存

`CarvingViewModel` 对 UI 暴露单一编辑状态，并区分加载、可编辑、只读错误、保存中和保存完成。加载旧碑刻不会修改数据库。

保存过程：

1. 校验文档至少包含一个有效笔画；
2. 编码完整文档，而非只编码本次新增笔画；
3. 保留原 `createdAt`、地点和景点关联；
4. 写入成功后再清除脏状态并返回；
5. 写入失败时保留编辑内容并展示可重试状态。

删除仍需确认。任何编解码或保存异常都不能退化为写入 `[]`。

## 测试

### 共享单元测试

- V2 编码后解码保持文档语义；
- 不同画布尺寸还原相同的归一化几何；
- 压力、时间、颜色、笔刷和笔宽正确保留；
- V1 顶层数组被识别并稳定转换；
- V1 转换不会改写原字符串；
- 损坏、空白、未知版本和非有限数值返回明确错误；
- 编辑已有文档后保存包含原笔迹与新增笔迹；
- 撤销和清空遵守完整文档顺序；
- 碎屑种子和路径缓存 key 具有确定性。

### Android 验证

每次 UI 或运行时改动后严格执行项目 Iron Law：

1. `./gradlew installDebug`；
2. 启动 Android 模拟器中的应用；
3. 使用 `adb shell monkey`、`adb shell input tap/swipe` 完成新建、续刻和列表打开；
4. 使用 `adb shell screencap` 保存改动前后截图；
5. 检查 logcat 无相关崩溃或序列化异常。

### iOS 验证

- 使用 `xcodebuild` 构建并安装到 iPhone 模拟器；
- 通过 Maestro 黑盒交互完成地点选择、新建、书写、撤销、保存、列表预览、重新打开和续刻；
- 保存关键步骤截图并检查系统日志；
- 验证空保存、损坏数据和返回未保存行为。

### 跨端数据验证

至少准备一份 Android UI 实际生成的 V2 数据和一份 iOS UI 实际生成的 V2 数据。从各自应用容器导出 `strokeData`，写入另一端测试数据库并通过正式碑刻列表打开，验证：

- 两端笔画数量、顺序、颜色和笔刷一致；
- 归一化关键点误差不超过 `0.001`；
- 预览与编辑画面保持相同构图；
- 在另一端续刻保存后，原笔迹没有丢失。

## 完成标准

只有共享测试、Android 设备流程、iOS 模拟器流程和双向数据验证全部有新鲜证据时，跨平台碑刻才算完成。仅编译成功、仅一端可见或仅使用伪造截图都不满足完成标准。
