# MapChina 产品重塑设计

> 日期：2026-07-09  
> 状态：待用户 review  
> 方向：半自动中国足迹记录器

## 1. 产品定位

MapChina 从“地图、景点、社区、成就的功能集合”重塑为 **半自动中国足迹记录器**。

一句话定位：

> 自动发现你可能到过的地方，由你确认点亮中国。

北极星用户是 **足迹记录者**。产品优先解决三个问题：

1. 我已经去过中国哪些省、市、区和景点？
2. 我现在或过去的旅行，怎样低成本补成可信足迹？
3. 我还差哪些地方，下一块版图应该去哪点亮？

社区、碑刻、图鉴和景点推荐都服务于这条主线。景点不是独立目的地数据库，而是帮助用户点亮足迹和发现下一站的入口。

## 2. 产品原则

1. **地图是主角**：打开 App 第一眼看到自己的中国足迹，不把核心价值藏进列表。
2. **用户确认优先**：系统可以建议，但足迹写入必须让用户理解并确认，降低误标焦虑。
3. **推荐服务点亮**：发现页推荐的不是泛旅游内容，而是“能帮我补地图”的景点、城市和主题路线。
4. **成长有仪式感**：成就、图鉴、碑刻、山河值统一成“山河成长体系”，强化留存。
5. **分享是结果，不是前置负担**：社区降级，不再占一级 Tab；分享在用户完成点亮、阶段成就或路线回顾后出现。

## 3. 功能优先级

### P0：足迹闭环

- 足迹首页地图
- 区域点亮和足迹等级：途经、小驻、深游
- 景点访问带出行政区足迹
- 当前位置足迹建议
- 待确认足迹队列
- 点亮后的成就反馈

### P1：发现下一站

- 未点亮区域推荐
- 附近可点亮景点
- 4A/5A 景点搜索和筛选
- 主题路线：五岳、江南古城、丝路、海岸线等
- 推荐理由：可点亮哪个区、市、省，距离当前足迹目标有多近

### P2：山河成长体系

- 勋章墙
- 图鉴
- 省份征服
- 统计
- 碑刻
- 阶段性分享卡片

### P3：社区和内容传播

- 游记和分享结果展示
- 公开故事流
- 分享页承接
- 网站 SEO 内容

社区不作为移动端 V1 的一级主入口。现有社区能力保留，但在信息架构上后移。

## 4. 导航架构

底部导航调整为四个 Tab：

| Tab | 定位 | 核心任务 |
| --- | --- | --- |
| 足迹 | 核心首页 | 看地图、确认建议、点亮区域、查看最近足迹 |
| 发现 | 推荐 + 补录 | 发现下一站、补录过去、搜索景点、确认待补录 |
| 山河 | 成长体系 | 成就、图鉴、统计、碑刻、省份征服 |
| 我的 | 账号设置 | 登录、同步、隐私、地图主题、导出和版本信息 |

现有 Tab 映射：

- 地图 → 足迹
- 景点 → 发现
- 社区 → 从一级 Tab 移除，作为分享/游记入口
- 我的 → 我的，但成长入口迁移到山河

## 5. 核心页面设计

### 5.1 足迹 Tab

足迹 Tab 是产品的第一屏，结构为“沉浸地图 + 轻量任务层”。

首屏内容：

- 全屏中国地图，默认展示已点亮省份和当前层级进度。
- 顶部状态卡：当前范围、已点亮数、完成度、下一目标。
- 智能建议条：展示 1 条最高优先级待确认足迹，例如“你可能到过杭州市西湖区”。
- 区域底部卡：点击区域后展示足迹等级、下级入口、景点入口、题刻入口。
- 右侧地图工具：回全国、当前位置、照片点位、分享、随机出发。

足迹页的主要 CTA 是 **确认点亮**，不是“浏览更多”。用户每完成一次确认，应立即看到地图颜色变化、山河值或成就反馈。

### 5.2 发现 Tab

发现 Tab 的定义是：**发现值得点亮的下一站**。

页面模块：

1. **待补录**
   - 当前位置建议
   - 景点访问带出的行政区建议
   - 用户曾经关闭但未处理的建议

2. **补地图推荐**
   - 推荐未点亮省、市、区中的高价值景点
   - 推荐理由必须明确，例如“可点亮黄山市 + 安徽省进度”
   - 支持按距离、5A/4A、未点亮优先排序

3. **附近可点亮**
   - 基于当前位置展示附近景点和行政区
   - 用户可一键标记景点，并确认是否同步点亮行政区

4. **主题路线**
   - 用图鉴和成就目标包装推荐
   - 示例：五岳、世界遗产、海岸线、丝路、江南古城

发现页保留搜索能力，但搜索结果需要围绕“能点亮什么”组织，而不是只列景点名称。

### 5.3 山河 Tab

山河 Tab 收纳所有成长与文化表达能力。

页面结构：

- 顶部山河等级卡：等级、山河值、下一等级差距。
- 今日/本周目标：例如“再点亮 1 个区县解锁百县行者”。
- 四个主入口：勋章、图鉴、征版、碑刻。
- 统计入口：作为山河账本的深层页面，不再藏在我的页。
- 最近解锁：展示最近成就和可分享节点。

山河 Tab 的作用是让用户回看进度、获得成就感，并产生再次点亮的动机。

### 5.4 我的 Tab

我的 Tab 简化为账号和控制台。

保留内容：

- 登录/账号信息
- 云同步状态
- 隐私和权限
- 自动标记足迹开关
- 照片标记开关
- 地图主题
- 导出和分享设置
- App 版本

迁出内容：

- 勋章、图鉴、征版、碑刻、统计迁移到山河。
- 游记和公开故事作为分享结果入口，不占主层级。

## 6. 半自动足迹闭环

### 6.1 V1 数据来源

V1 采用组合策略：

1. **景点访问带出足迹**
   - 用户标记景点为途经、小驻或深游。
   - 系统生成行政区建议：区、市、省。
   - 用户确认后写入 Footprint。
   - 如果用户拒绝，只保留景点访问记录，不写行政区足迹。

2. **当前位置建议**
   - 用户进入足迹页或点击当前位置。
   - 系统解析当前位置对应行政区。
   - 展示“是否点亮此地”的确认卡。
   - 用户选择足迹等级后写入。

### 6.2 V2 数据来源

V2 增加 **照片回溯**：

- 扫描用户授权的照片地理位置。
- 聚合成城市、区县、景点建议。
- 生成“过去足迹待确认”列表。
- 用户批量确认或逐条修正。

照片回溯权限敏感，必须作为独立引导，不能在 V1 阻塞核心体验。

### 6.3 建议状态

新增足迹建议概念：

```kotlin
enum class FootprintSuggestionSource {
    LOCATION,
    ATTRACTION_VISIT,
    PHOTO,
    MANUAL_SEARCH
}

enum class FootprintSuggestionStatus {
    PENDING,
    CONFIRMED,
    DISMISSED
}
```

每条建议至少包含：

- source：来源
- regionId：建议点亮区域
- regionName：区域名称
- parentPath：省/市/区路径
- suggestedLevel：建议等级，可为空
- confidenceLabel：高、中、低，用于 UI 展示
- createdAt：创建时间
- status：待确认、已确认、已忽略

V1 可先在 ViewModel 层组合现有数据，不一定立刻新增持久化表。若需要跨启动保留待确认队列，再引入 SQLDelight 表。

### 6.4 写入规则

- 景点访问不会静默点亮行政区，必须弹出确认。
- 用户确认区县足迹时，可自动补全父级市、省为“途经”，但确认卡需要说明。
- 用户选择更高等级时允许升级，不自动降级。
- 用户撤销自动建议时，只撤销本次建议写入，不删除已有手动足迹。

## 7. 视觉风格

新视觉方向：**清润山河账本**。

关键词：

- 清晰、可信、记录感
- 现代地图工具效率
- 东方山河的克制仪式感
- 少装饰，多状态表达

### 7.1 色彩

主色保留碧玉绿，但降低全局铺满感：

- 碧玉绿：用于已点亮、确认、主 CTA
- 山河金：用于成就、等级、完成节点
- 水蓝：用于定位、附近、推荐理由
- 石墨黑：用于正文和地图标签
- 宣纸白/冷灰白：用于背景

避免页面都变成单一绿色。发现页可以引入水蓝，山河页引入金色，我的页保持中性。

### 7.2 组件语言

- 地图上的信息层使用半透明浮层，减少遮挡。
- 列表卡片减少大圆角，统一 8-16dp 半径。
- 推荐卡必须突出“可点亮什么”，景点图片是辅助。
- 成就卡更有仪式感，但不牺牲可读性。
- 图标优先使用 Material Icons，后续可逐步替换为统一山河线性图标。

### 7.3 动效

动效继续沿用“山水流动”方向，但收敛到关键反馈：

- 确认点亮：地图区域染色 + 轻微涟漪
- 建议卡出现：从底部轻推入，不抢地图
- 成就解锁：顶部 banner 优先，重大节点再弹窗
- Tab 切换：轻量淡入，不做大幅位移

## 8. 增长闭环

MapChina 的增长不从“刷社区”开始，而从“完成一块版图”开始。

### 8.1 激活

新用户进入后先完成一个低成本动作：

1. 选择已经去过的省份，快速点亮 3 个以内。
2. 或允许当前位置，确认当前所在地。
3. 或从发现页搜索一个去过的景点。

激活成功标准：首日完成至少 1 个足迹点亮。

### 8.2 留存

留存来自未完成感：

- 下一块未点亮区域
- 省份完成度
- 图鉴目标
- 附近可点亮提醒
- 待补录队列

### 8.3 分享

分享节点：

- 点亮一个新省份
- 完成一个省份征服
- 解锁重要成就
- 完成一条主题路线
- 年度足迹总结

分享卡片需要带明确视觉资产：当前地图、完成度、成就名、MapChina 品牌。

### 8.4 召回

V1 先做产品内召回：

- 发现页展示“离你最近的未点亮景点”
- 山河页展示“再点亮 1 个即可解锁”
- 我的页显示同步和待处理状态

系统通知、邮件、社区传播放到后续阶段。

## 9. 信息架构到代码的映射

现有模块可以较好承接新设计：

- `ui/map` 继续承接足迹 Tab
- `ui/attraction` 改造为发现 Tab
- `ui/achievement`、`ui/stats`、`ui/carving` 聚合为山河 Tab
- `ui/profile` 收敛为账号设置
- `ui/community` 从一级导航移除，保留为分享和游记入口

建议新增或调整：

- `ui/discover`：发现首页容器，可复用 attraction 的列表和 ViewModel 能力
- `domain/model/FootprintSuggestion.kt`：足迹建议模型
- `domain/service/FootprintSuggestionService.kt`：从位置、景点访问、照片生成建议
- `ui/footprint` 或 `ui/map/SuggestionCard.kt`：足迹建议确认卡
- `ui/shanhe`：山河首页容器，聚合成就、图鉴、碑刻、统计

## 10. 数据流

### 10.1 景点访问到足迹建议

```text
用户标记景点
→ AttractionViewModel.markVisit()
→ 写入 AttractionVisit
→ FootprintSuggestionService 根据 attraction.regionId 生成建议
→ UI 展示确认卡
→ 用户确认等级
→ FootprintRepository.upsert()
→ AchievementRepository 刷新
→ 地图和山河进度更新
```

### 10.2 当前位置到足迹建议

```text
用户进入足迹页或点击当前位置
→ LocationProvider 获取坐标
→ RegionRepository 解析所在行政区
→ FootprintSuggestionService 生成 LOCATION 建议
→ UI 展示确认卡
→ 用户确认或忽略
→ 写入 Footprint 或记录 dismissed
```

### 10.3 推荐到点亮

```text
DiscoverViewModel 汇总未点亮区域、景点、当前位置
→ 推荐卡展示“推荐原因”和“可点亮范围”
→ 用户打开景点详情或直接标记
→ 进入景点访问到足迹建议流程
```

## 11. 错误和边界处理

- 定位失败：展示手动搜索入口，不阻塞足迹页。
- 行政区解析失败：展示坐标附近景点建议，不直接点亮。
- 用户拒绝权限：发现页和手动补录保持可用。
- 建议误判：用户可以忽略，系统不反复打扰同一建议。
- 离线状态：可手动点亮本地数据，云同步延后。
- 景点无 regionId：只写景点访问，不生成行政区建议。
- 成就刷新失败：足迹写入成功优先，成就稍后重试。

## 12. 验收和测试

任何 UI 或运行时变更交付前必须遵守项目铁律：

1. `./gradlew installDebug`
2. 启动 Android app
3. 用 `adb shell monkey`、`adb shell input tap/swipe` 复现主流程
4. 使用 `adb shell screencap` 截取变更前后截图
5. 未完成设备验证，不报告 UI/runtime fix 完成

产品验收场景：

- 首次进入足迹页能清楚看到地图进度和下一目标。
- 当前位置建议能出现、确认、忽略。
- 标记景点后能生成行政区点亮建议。
- 发现页推荐卡能说明“为什么推荐”和“能点亮什么”。
- 山河页能展示等级、成就、图鉴、碑刻、统计入口。
- 我的页不再承载成长功能，设置和账号路径清晰。
- 社区不在底部一级导航中出现。

## 13. 分期计划

### Phase 1：信息架构和主流程

- 底部导航改为足迹、发现、山河、我的。
- 足迹页加入智能建议条。
- 发现页重组为推荐 + 补录。
- 山河页聚合成长入口。
- 我的页收敛为设置。

### Phase 2：半自动建议模型

- 引入 FootprintSuggestion 模型。
- 景点访问生成建议。
- 当前位置生成建议。
- 建议确认卡和忽略逻辑。

### Phase 3：推荐能力增强

- 未点亮区域推荐。
- 附近可点亮。
- 主题路线。
- 推荐排序和理由。

### Phase 4：增长和分享

- 成就分享卡。
- 省份完成分享卡。
- 年度足迹总结。
- 社区和网站承接。

### Phase 5：照片回溯

- 相册权限引导。
- EXIF 聚合。
- 历史足迹待确认队列。
- 批量确认。

## 14. 非目标

本轮不做：

- 复杂社交 feed 重构
- AI 行程规划
- 商业化订阅
- 完整照片回溯
- 大规模后端推荐系统

这些可以在“足迹记录闭环”跑顺后继续扩展。
